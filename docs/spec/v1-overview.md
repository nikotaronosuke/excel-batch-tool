# v1 Overview — Excel Batch Tool(開発コードネーム)

正式製品名: 未定

## 目的

Windows 上で、複数の Excel Workbook・多数の Sheet・CSV を、
Microsoft Excel を一つずつ開くことなく、完全ローカルで安全に一括処理する
デスクトップアプリを提供する。

## 対象ユーザー

- 毎月・毎週、同じ Excel 転記/統合/変換作業を人力で行っている事務・業務担当者
- クラウドソーシングで Excel 作業を外注している/受注している人
- IT 部門ではないため、マクロ・スクリプトを自作できない非技術者

## 解決する課題

クラウドソーシング市場調査(docs/research/market-summary.md)で確認された、
現在も人力で行われている作業:

- 複数 Excel ファイルの統合
- 数十〜数百 Sheet への転記
- CSV 形式への変換 / CSV から複数 Excel への振り分け
- 重複・空欄・表記揺れの確認
- 毎月同じ Excel 処理の繰り返し
- Workbook 間の反復転記

## 中心価値

「Excel 機能を大量に搭載すること」ではなく:

- 大量 Workbook をまとめて扱える
- Excel 本体不要
- 完全オフライン
- ファイルを外部へ送らない
- 変更前に確認できる
- バックアップできる
- 壊す可能性がある Workbook には安易に書き込まない

## v1 機能候補

Phase 0〜5(docs/implementation/roadmap.md 参照):

0. Workbook 安全解析(読み取り専用)
1. 複数 Excel 統合(1A: 表データの縦結合 / 1B: Sheet 集約)
2. 複数 Workbook / Sheet への一括変更
3. CSV から Workbook / Sheet への振り分け
4. 重複・空欄・形式異常等のデータチェック
5. 処理レシピ・履歴

全変更系機能の共通フロー:
変更予定解析 → 変更前プレビュー → 自動バックアップ → 実行 → 処理ログ

## 非対象(v1)

- .xls(旧バイナリ形式)
- **手書き**(2F-R の判断どおり対象外)
- 写真撮影などで**紙が大きく歪んだ** PDF(台形のひずみ)
- 1 ページが極端に大きい PDF(図面など)
- 1 ページに複数件の帳票
  ※ PDF そのものは 2026-08-29 に方針を変更した。2F-R の実現性ベンチマークが
  GO(条件付き)だったため、**文字情報を持つ PDF は Phase 2F-A、
  スキャン PDF の OCR と確認・修正は Phase 2F-B1、
  傾き補正・スキャン表・定型帳票・印は Phase 2F-B2、
  全方式の統合と実案件相当の総合試験は Phase 2F-B3 で対応**
  (OCR は別配布の Offline OCR Pack。本体だけでも文字 PDF は読める)。
  **Phase 2F は 2F-B3 をもって CLOSE**(D-037)。
  傾いた罫線表も 2F-B3 で読めるようになった(傾きを直す向きの誤りを修正)
- AI 内蔵機能
- VBA 編集
- Mac / Web 版

## オフライン方針

- クラウドサービス・Web API・外部 AI API・ログインを使わない。
- アプリ自身のネットワーク通信機能を持たない(実装しない)。
- 配布は self-contained Windows x64 build(2026-08-28 確立、D-011)。
  利用者に .NET Desktop Runtime の事前導入を要求せず、ネット接続なしで導入できる。

## ファイル安全性方針

- Excel 読み書きは Microsoft Open XML SDK を中心にする(Office Interop 禁止、
  Excel 本体依存禁止)。
- 読み取りは物理的に書き込めない開き方(FileAccess.Read)で行う。
- 書換系機能は必ず「変更予定解析 → プレビュー → 自動バックアップ → 実行 →
  ログ」を通す。
- 解析で ⚠(注意)/ ✖(非対応)と分類された Workbook には安易に書き込まない。
  分類ルールは docs/decisions.md D-004。

### 出力ファイルの安全性(Phase 1A で確立 / D-012)

- 統合・変換の出力は**新規ファイルの新規作成のみ**。既存ファイルを上書きしない。
- 出力先が既存ファイル、または入力ファイルと同一パスの場合は Block。
- 出力は「同一ディレクトリの一時ファイルへ生成 → Open XML として再度開いて
  最低限の検証 → 最終パスへ移動」の順で確定する。失敗時は一時ファイルを削除し、
  壊れた中途半端な .xlsx を最終出力として残さない。
