## PDF 対応(Phase 2F)から持ち越した課題

2F-B1 / B1.1 / B2 で「後で」としたもののうち、**2F-B3 で解消しなかった**もの。
急ぎではないが、PDF まわりに手を入れるときに見る。

- 縦書き・回転ページ(現状は文字の並び順のまま)
- 段組の扱い
- 表の結合セル(現状は素直に展開)
- Pack の版と本体の版の対応。いまは版違いを利用者向けの文言にするところまで。
  目録に対応する本体の版を書いて事前に照合するのは未実装
- 印だけのページ(文字がほとんど無いページ)は傾きを測れないため、
  傾いていると自動確定が 0 になる。実害は「全部人が見る」だけで誤確定は 0
- 罫線表の劣化版で、行数が期待どおりにならないページが残る(3 ページ中 1)

### 処理設定(レシピ)から繰り越し(D-028)

- レシピの書き出し / 読み込み(他 PC への持ち出し)。固定値を含み得るため、
  外部共有時の扱いと版の移行設計が要る
- レシピのクラウド同期(現状は完全ローカルで、行う予定は無い)
- Phase 1 系(表をまとめる・シートをまとめる)のレシピ対応
- レシピに「よく使う転記先シート名」を覚えさせるか
- 時刻を決めた自動実行 / スケジュール(現状は行わない方針)
- レシピの暗号化が必要かの評価(現状は平文。固定値・項目名を含み得る)

### PDF 調査から繰り越し(D-032)

- 罫線なしスキャン表の実測(現状は不得意として明示)
- 二重読み照合(v5 × japan v4)の統合精度の実測
- deskew(傾き補正)の実装と、傾きスキャンでの領域指定・チェックボックス再測定
- PP-StructureV3(Python sidecar)の要否再評価(罫線格子方式で足りない場合のみ)
- 手書き対応の可否(実データが無い限り判定不能。当面は対象外と案内)
