### いちばん大事だった課題: 項目が消えないこと

B1.1 で分かった「帳票 813 項目中 89 件が、どの領域にも読まれず結果から消える」を
無くした。**指定した項目の数と、確認に出る件数を必ず一致させる。**
読み取りが見つからない項目は「見つからない」として 1 件残し、
指定した領域の位置を使って元のページのその場所を見ながら手で入力できる。
未確認のまま残れば出力は Block。

- 傾き補正: 0.3 度未満は直さない / 6 度超は直さず Block /
  角度を測れないページは回さずそのまま読む(止めない)。
  **確認の赤い枠は必ず元のページの座標へ戻す**(往復して戻ることをテストで固定)
- 罫線のある表: 罫線から格子を作って行・列へ戻す。
  外枠の細い線が拾えなくても、その外側の文字を捨てない
- 罫線のない表: 文字の位置のまとまりから列を決めて戻す
- 定型帳票: 1 ページ 1 件。全ページ OCR の結果を領域で割り当てる方式
  (2F-R の「切り出して読むほうが悪い」という実測を踏襲)。
  項目名を手がかりにページごとのずれを吸収する
- 印: 文字として読まず、箱の中とラベルの周りの黒画素の割合で判定。
  差が小さい・薄いときは自動で決めず人へ回す
- ページの種類(文章 / 罫線表 / 罫線なし表 / 帳票)は自動で判定する。
  記入欄の下線を表と誤判定しない(Phase 2F-A の再発防止)
- 確認の画面は B1.1 のものをそのまま使う。別の危ない確認画面を作らない
- 控えへ mode / 傾きを直したページ数 / 表・帳票のページ数 /
  指定した項目の総数 / 見つからなかった件数 を追加

### 実装中に見つけた、想定と違った点(Phase 2F-B2)

1. **傾きの推定が罫線に引きずられた。** 傾き 0 度の罫線表が「6 度超」と判定されて
   止まった。罫線を先に取り除いてから文字の行だけで測るようにした
2. **「角度を測れない = 止める」は厳しすぎた。** 測れないページは回さずに読む、へ変更
3. **細い外枠の罫線が消え、4 列の表が 2 列になった。** 罫線の外側に文字があれば
   そこにも区切りを足す。判断には文字の中心を使う(端で判断すると行が 1 つずれた)
4. **向きの判定を弱めたら読み取りが落ちた**(罫線表 61.3% → 38.7%)。既定へ戻した
5. **傾いた罫線表は実用にならない**(まっすぐ 61.3% に対し 2 度傾きで 4.8%)。
   崩れた表を出さず、理由を示して止める。2F-B3 で扱う
6. **印が 0/6 だったのは fixture のほうが細すぎた。** 線を 2px(300dpi で 0.17mm)で
   描いていた。実際のペン相当(6px)にすると clean / 劣化とも 100%。
   **測定結果が悪いときは、まず fixture が現実的かを疑う**
7. **誤確定が 6 件残っていた原因は、全部「両方のモデルが同じ間違いをした」だった。**
   件数だけでなく中身を出したら、帳票 4 件は「S001-24」→「SO01-24」(0 が O)、
   表 2 件は上下逆の切り出し(「A0096」→「9600」)。自信は 98〜99.8% あり、
   閾値では消えない。**一致も自信も根拠にならない**ので「形」で見る判定を足した
   (`FieldAutoAcceptPolicy` / `ColumnShapeGuard`)。すべての fixture で誤確定 0 へ
8. **列の形に記号を数えていたら、正しいセルまで人へ回っていた。**
   桁区切りを数えると金額の「999」と「1,234」が別の形になる。記号は数えない

## Phase 2F-B1.1(OCR 確認の安全性補正)で完了した内容(2026-08-29)

> 以下は **2F-B1.1 を終えた時点の記録**。当時の見通しをそのまま残す。
> Phase 2F は 2F-B3 をもって CLOSE 済み(D-037)。

⚠ **Phase 2F は進行中のまま。** 傾き補正・スキャン表・大量定型帳票・checkbox は
2F-B2、最終統合は 2F-B3(D-035)。

レビューで挙がった「確認 UI に元 PDF の画像が無い」「まとめて確認済みにできてしまう」
という 2 点は、どちらも**人が安全に確認する**という完成条件に直結するため、
2F-B1 を正式 COMPLETE にする前の必須補正として実施した。

- **元の PDF のページ画像を出す。** 選んだ項目のページへ自動で移動し、
  読み取った位置を赤い枠で示す。ページ送り / 拡大 / 縮小 / 100% / 全体表示
- **枠が小さすぎるときだけ、読める大きさまで自動で寄る。** ページ全体を表示した
  倍率(A4 で約 24%)では 1 行が 10 画素ほどにしかならず、原文と見比べられないため。
  利用者が自分で拡大しているときはその倍率を触らない
- 同じページの中で選び直したときは、画像を描き直さず枠だけ動かす
- **「表示中をすべて確認済みにする」を削除**(指示の案 A)。代わりに
  次 / 前の要確認へ、修正して確認 → 次へ、元のままで確認 → 次へ、
  および Enter / Ctrl+Enter / Esc / F3。**未確認を飛び越えない**
- 一覧の絞り込みを「最初の分類」で行うようにした。確認済みにしても行が消えないので、
  何を確認したのかが見えるし取り消せる。「自動確定も表示」で自動確定も原文と見比べられる
- 読取不能も原文とその位置を見て手で入力できる。読めなければ未解決のまま出力 Block
- ページ画像は今のページと前後 1 ページの **3 枚だけ**手元に置く。一時ファイルは作らない
- Pack の版がアプリと合っていない場合を、.NET の内部的な文言ではなく
  利用者向けの文言に言い換えた

### 誤自動確定の再測定(Phase 2F-B1.1)

2F-B1 で 0.12%(813 中 1 件)と報告した誤確定は、**測り方の誤りだった**。
その 1 件は「日付の項目を正しく読んだ領域」で、読まれなかった売上の値を
いちばん近い領域として結び付けていたもの(= 検出漏れ)。

「その項目を読もうとした領域」だけを対応付けるよう直した結果、
**閾値 0.98 / 0.985 / 0.99 / 0.995 / 0.999 のすべてで誤確定 0 件**
(帳票 clean・帳票 degraded・文章 clean・文章 degraded の全 fixture)。
対応付けの下限を 0.2〜0.7 で振っても 0 件。

閾値は **0.98 のまま**(上げても安全は増えず自動確定率だけが 24% → 14% に落ちる)。
追加の gate も入れない。誤確定を 0 にしているのは閾値ではなく
「2 つのモデルが一致し、かつ自信が足りているときだけ自動確定する」という条件そのもので、
これを不変条件としてテストで固定した。

検出漏れ(帳票 clean で 813 項目中 89 件)は OCR の拾い漏れであって
確認の安全とは別問題。2F-B2 以降の課題として残す。

- 二重読み(多言語 rec + 日本語専用 rec)。**単一エンジンは採らない**。
  検出は 1 回だけ行い、同じ切り出し画像を 2 つの認識モデルへ通す
- 統合規則は 11 方式 × 3 閾値を Ground Truth と機械照合して選んだ
  (research/PdfFeasibility/PdfFusionBench)。
  一致 + 自信 0.98 以上 → 自動確定 / 一致しても自信不足 → 要確認 /
  **割れたら必ず要確認**(どちらも自信満々でも自動確定にしない)
- 割れたときに出す文字は「空白を除いてすべて ASCII なら多言語 rec、
  日本語が 1 文字でも混ざれば日本語 rec」。この閾値も測って決めた
- 状態は 自動確定 / 要確認 / 読取不能 / 確認済み。
  「修正して確認」と「元のままで正しいと確認」の両方ができ、
  **一覧を開いただけでは確認済みにしない**
- 画面には両モデルの読みと自信を並べて出す。どちらが違うのかを見て直せる。
  「要確認だけ表示」で絞れる(120 ページを 1 件ずつ見せない)
- ページ単位の振り分け。混在 PDF は**文字のページを OCR に通さない**。
  ただし表のページとスキャンのページが混ざる PDF は Block(構造を揃えられない)
- 傾き・スキャン表は、**認識を始める前に**画像だけ見る安い確認で見つけて止める。
  無理に文章として出力しない
- 出力・上書き禁止・作業用ファイル・取り消し・読み直し照合・snapshot は
  2F-A のものをそのまま再利用。OCR 専用の書き出しは作らない
- 控えは OCR を通した場合だけ schemaVersion 2。件数だけを残し、
  **読み取った文字そのものは複製しない**
- 中止できる。中止すると元の PDF は変わらず、出力も控えも作業用ファイルも残らない
- **Offline OCR Pack として分離**。本体は OCR ランタイムを一切参照せず、
  `ocr` フォルダーから実行時に読み込む。Pack が無くても本体は普通に起動し、
  文字情報のある PDF はそのまま読める
- Pack は目録(サイズ + SHA-256)で検査してから読む。欠損・改変・未知の版は
  **native の読み込みに入る前に**文言で Block する
- 実行時のダウンロードは無い(モデル取得は Pack を組み立てるときだけ)。
  モデル置き場を退避しても動くことを実測で確認
- **Intel MKL は使わない**(再配布条件に曖昧さが残るため)。
  推論は ONNX Runtime(MIT)、行列演算は OpenBLAS(BSD-3)
- VC++ ランタイムは Pack へ app-local 同梱。**製品本体は Windows 標準の
  Universal CRT だけ**(PE の import を全ファイル確認)

### 実装中に見つけた、想定と違った点(Phase 2F-B1)

1. **PP-OCRv5 と日本語専用 rec は同じプロセスに載らない。** 2F-R の所見を再実測し、
   3.x runtime では device を問わず旧形式モデルが動かないことを確認した。
   二重読みを 1 プロセスで成立させられるのは 2.x 側だけ
2. **認識器は NaN / Infinity を返す。** そのまま閾値と比べると
   「自信 = 無限大」で自動確定を通ってしまう。有限でない自信は必ず 0 に倒す
3. **切り出しは 180 度回ることがある。** 向き判定を通さないと電話番号が逆順に読まれた
4. **Sdcb の検出枠 score 絞り込みは native ごと落ちる。** 枠が画像の外へ
   わずかにはみ出したときに保護されていないメモリを読む(120 ページで再現、
   落ちるページは実行ごとに変わる)。.NET から捕まえられないので呼ばない形にした。
   外しても枠は +1% しか増えず、増えた分は自信が低いので要確認へ回る
5. **推論の実行方式で 7 倍違った。** OpenBLAS 22.8 秒 / oneDNN 23.2 秒 /
   **ONNX 3.3 秒**(1 ページあたり)。速いほうがライセンスも明確だった
6. **文字種の閾値を 5 割にすると日本語の文章が落ちた。**
   `金額:4,917,087円` のように ASCII が多数でも末尾に日本語が付く領域で
   多言語 rec を選んでしまい、完全一致が 100% → 75% に。全 ASCII のときだけに変更

## Phase 2E(CSV 変換・整形 v1)で完了した内容(2026-08-28)

Excel / CSV の表を、別のシステムで使う項目名・並び順の新しい CSV にする(D-030)。

- 出力する列を 1 件ずつ指定する。データ元の列 / 固定値 / 空欄の 3 種類。
  項目名の変更・並べ替え・不要列の除外・同じ列の複数出力・固定値列の追加
