# Excel Batch Tool

> **Excel Batch Tool は開発コードネームです。正式な製品名は未定です。**

Windows 上で、複数の Excel Workbook を Microsoft Excel を開くことなく、
**完全ローカル**で安全に一括処理することを目指しているデスクトップアプリです。

**現在は初期開発段階です。** 完成品・安定版ではありません。

## 現在できること

**入力した Excel ファイルは、解析でも統合でも一括変更でも転記・突合でも一切変更しません。**
値を書き換える機能も、元ファイルはそのままにして別名のファイルを新しく作ります。

### 1. 読み取り専用の Workbook 解析

Excel ファイルを**書き換える前に安全に把握する**ための解析です。

- `.xlsx` ファイルの Drag & Drop / ファイル選択(複数同時)
- Workbook ごとの情報表示
  - シート数・シート名・使用範囲・概算行数/列数・ファイルサイズ
- 書き換え時に注意が必要な要素の検出
  - 数式 / 結合セル / 図形 / グラフ / 画像 / ピボットテーブル / 外部参照 /
    シート・ブック保護 / テーブル / データ入力規則 / 条件付き書式 /
    コメント / 定義名 / ハイパーリンク / OLE・ActiveX / マクロ関連 など
- 解析結果の分類表示
  - ✅ 通常 / ⚠ 注意が必要 / ✖ 現在非対応

### 2. 表データの縦結合

複数の `.xlsx` に分かれた同じ形の表を、1 つの**新しい** Workbook にまとめます。

- 1 ファイルにつき 1 シートを選んで縦に結合(表の 1 行目を見出しとして扱います)
- 列の順序が違っても、同じ見出し名なら対応付けて結合
- どのシートの見出し順で列を並べるかを「基準」として選択(既定は先頭のシート)
- 実行前のプレビューで、対象数・出力予定行数・出力する列・問題点を確認
  - 見出しの不一致(不足 / 余分)、空の見出し、重複した見出しを事前に検出
  - 数式や結合セルを含むシートは、意味が壊れる可能性があるため対象外として明示
  - 実行できない問題が 1 件でもある間は、作成ボタンを押せません
- 「元ファイル」「元シート」列を先頭に追加可能
- 出力は新規 `.xlsx` のみ。既存ファイルは上書きしません

### 3. シートの集約

複数の `.xlsx` から選んだシートを、1 つの**新しい**ブックにシートとして並べます
(2. と違い、行データは混ぜません)。

- 1 つのブックから複数シートを選択可能。非表示シートは一覧で明示されます
- 保持するもの: セルの値と型、日付、書式(フォント・塗りつぶし・罫線・配置・
  表示形式)、行の高さ / 非表示、列の幅 / 非表示、結合セル、ウィンドウ枠の固定、
  シートの表示状態、シートの保護
- 出力シート名は自動で一意になり、その場で編集もできます
- シートの表示状態は「表示 / 非表示 / 非常に非表示」を区別して引き継ぎます
- 基本的な印刷設定・ページレイアウトも引き継ぎます(余白、印刷オプション、
  用紙・向き・拡大縮小、文字だけのヘッダー/フッター、改ページ位置、
  印刷範囲・印刷タイトル)。**完全再現ではありません**: プリンター固有の設定、
  ヘッダー/フッターの画像、複雑な名前定義を含むシートは対象外として検出します
- 現在のバージョンで保持できない要素(数式、グラフ、図形、画像、テーブル、
  ピボットテーブル、コメント、
  オートフィルター、リッチテキストなど)を含むシートは、
  **黙って削除せず**プレビューで理由を示して対象外にします
- 一般的な入力規則を保持します(直接指定のプルダウン、同じシート内の範囲を使う
  プルダウン、数値 / 日付 / 時刻 / 文字数の制限)
- **別シートのマスタを参照するプルダウン**も保持します。候補一覧を置いたシートも
  いっしょに選んでおけば、集約後のシート名に合わせて参照先を書き直します。
  単純な「ブック全体の名前定義」を使うプルダウンにも対応します
- INDIRECT / OFFSET などの関数を使う入力規則、連動プルダウン、シート固有の名前定義、
  他のブックを参照する入力規則、ユーザー設定の数式、複雑な新形式(x14)の規則は
  事前に検出して対象外にします
- Web / メールへのリンクと、集約対象のシートを指すブック内リンクを保持します
  (リンク先へのアクセスは行いません)。ローカルファイルへのリンク、集約対象外の
  シートを指すリンク、複雑な参照は事前に検出して対象外にします
- **数式を使わない基本的な条件付き書式**を保持します(重複する値 / 一意の値 /
  上位・下位 / 平均より上・下)。適用範囲・優先順位・「条件を満たす場合は停止」も
  そのまま引き継ぎます。**条件付き書式の完全対応ではありません**:
  数式を使うルール、指定の値を含む / 日付などの条件、カラースケール、データバー、
  アイコンセット、テーマ色を使う書式、新しい形式(x14)の条件付き書式は
  事前に検出して対象外にします
- 出力は新規 `.xlsx` のみ。既存ファイルは上書きしません

> 現在のバージョンはシートの完全なコピーではありません。上記の基本要素だけを
> 引き継ぎます。

### 4. 複数ファイルのセルをまとめて変更

複数の `.xlsx` で、選んだシートの**複数のセル**へ異なる文字・数値をまとめて入力します。

例(この 3 件を、選んだすべてのシートへ適用):

- B2 → 確認済み
- F8 → 1500
- H10 → 空欄にする

「セル・種類・値」の一覧は画面で編集でき、表計算からコピーした
タブ区切りの 3 列を貼り付けて追加することもできます。
同じセルを 2 回指定した場合はエラーとして扱います
(どちらかの値を勝手に採用することはしません)。

- **元のファイルは変更せず、同じフォルダーに `<元の名前>_変更済み.xlsx` を作ります**
  (接尾辞は変更できます)。同じ名前のファイルが既にある場合は作成しません
- 1 つのブックから複数シートを選べます。その場合の出力は 1 ファイルで、
  選んだすべてのシートの指定セルが変わります
- 入れられるのは**文字 / 数値 / 空欄にする**の 3 つです。書式(セルの色・罫線・
  表示形式)は元のまま変わりません
- 変更するのは対象のシートだけです。グラフ・図・画像・テーブル・条件付き書式などは
  **一切触らないのでそのまま残ります**
- 変更内容は、作成したファイルの隣に `<出力名>.xlsx.audit.json` として記録します
  (完全にローカルのファイルです)

**Excel ファイルを自由に一括編集できるわけではありません。** 次のものは事前に検出して
対象外にします。

- 数式を含むブック(計算結果が古いまま残るため)
- シートが保護されているもの
- 対象セルが結合セル・入力規則・ハイパーリンク・文字ごとの書式(リッチテキスト)を
  持つもの
- 対象セルがファイル内に存在しないもの(空のセルを新しく作ることはしません)
- 日付・時刻・通貨・パーセントなど、値の種類によって表示が変わりうる表示形式のセル
- ピボットテーブルのあるシート、外部データ接続・外部参照を含むブック
- Excel の形式として問題がある(壊れている)ファイル

対象のうち 1 セルでも上記に当てはまる場合、安全な分だけを部分的に適用することはせず、
実行そのものを止めて理由を表示します。

日付として入力する機能、検索して置換する機能、元のファイルを直接書き換える機能は
まだありません。

### 5. 表から転記(キーで一致する行を探して入力)

Excel / CSV の表から**キーが一致する行**を探し、選んだ Excel ファイルの指定セルへ
項目をまとめて転記します。

例(データ元の「店舗コード」と、転記先シートの A1 で対応付ける):

| 店舗コード | 担当者 | 売上 |
|---|---|---|
| OSAKA | 佐藤 | 1500 |
| KYOTO | 田中 | 1800 |

- 担当者 → D5(文字)
- 売上 → F8(数値)

↓ 大阪.xlsx(A1 = OSAKA)には 佐藤 / 1500、京都.xlsx(A1 = KYOTO)には 田中 / 1800。

- データ元は `.xlsx` と `.csv` に対応します。CSV は **UTF-8 と Shift_JIS(CP932)**
  を自動で判別し、引用符・引用符内のカンマや改行も正しく読みます
- `.xlsx` では**項目名の行を指定**します(自動では推測しません)
- **元のファイルもデータ元も変更せず**、同じフォルダーに
  `<元の名前>_転記済み.xlsx` を作ります
- 転記した内容は、どのデータ元のどの行から取ったかも含めて
  `<出力名>.xlsx.audit.json` に記録します
- すべて**完全にオフライン**で動きます

**キーは文字として完全に一致するものだけを対応付けます。** 大文字小文字・前後の空白・
全角半角は区別し、表記のゆれを勝手に吸収することはしません。次の場合は事前に検出して
対象外にします。

- 一致する行がデータ元に無い / 2 件以上ある
- キーの列やキーのセルが文字列でない(空欄・数値・数式など)
- 転記する値が空欄、数式、日付・通貨・パーセントなどの表示形式の数値
- 転記先が「4. セルをまとめて変更」と同じ理由で変更できないセル
- 対応付けの中で転記先セルが重複している / キーのセル自身を転記先にしている

**次の機能はまだありません。** 表記ゆれをあいまいに一致させること、
数式・日付の書き込み、空欄の転記、行の追加、検索して置換すること。

「どんな Excel でも自動で転記できる」わけではありません。

### 6. 表を突合して更新(キーで行同士を照合)

商品コードなどの**キーが同じ行**を探し、Excel / CSV の表から既存 Excel 表の
指定した列をまとめて更新します。行の順番が違っていてもキーで対応付けます。

例(商品コードで照合):

| 商品コード | 単価 | 在庫 |(データ元)
|---|---|---|
| A001 | 1200 | 10 |
| A002 | 1500 | 20 |

→ 転記先の表で A001 / A002 の行を探し、単価と在庫の列だけを書き換えます。
キーの列名はデータ元と転記先で違っていてもかまいません
(例: データ元は「SKU」、転記先は「商品コード」)。

- **既存の行だけを更新します。** データ元にしか無いキーで行を追加せず、
  転記先にしか無いキーの行も削除・空欄化しません。何件が一致し、
  何件が片側だけかはプレビューの集計で確認できます
- キーは文字として**完全に一致**するものだけを対応付けます
  (大文字小文字・前後の空白も区別)
- 同じキーが 2 行以上ある場合、それが更新に使われるなら中止します
  (どの行を使う・更新するかを勝手に決めません)
- 転記先の項目名の行は指定でき、列の位置がシートごとに違っても
  **列名**で対応付けます。無関係な列はそのまま残ります
- 元のファイルもデータ元も変更せず、同じフォルダーに
  `<元の名前>_更新済み.xlsx` を作ります。更新内容は控えファイルに、
  どのデータ元のどの行 → どの行のどのセルかまで記録します
- 表の大きさは動作を確認した範囲(1 シートあたり 10 万行)までを対象とします

**次の機能はまだありません。** 行の追加・削除、複数列を組み合わせたキー、
表記ゆれのあいまい一致、数式・日付の書き込み、空欄の転記、検索して置換すること。
2 つの表を「完全に同期」させる機能ではありません。

### 7. CSV を変換(別のシステムで使う項目・並び順にする)

Excel / CSV の表を、**別のシステムで使う項目名・並び順の新しい CSV** にします。
システムから出した CSV をそのまま別のシステムへ取り込めない、というときに使います。

例(商品 CSV を別システム用に整える):

| 元の CSV | → | 作る CSV |
|---|---|---|
| 商品コード, 商品名, 価格, 在庫, 内部メモ | | 商品番号, 名称, 販売価格, 在庫数, 公開状態 |

- 出力する項目は **1 つずつ自分で決めます**(元の項目を選ぶ / 固定値を入れる / 空欄にする)
- **項目名を変えられます**(`価格` → `販売価格`)
- **並び順を変えられます**(↑ ↓ で入れ替え)
- **出さない項目を選べます**(`内部メモ` は外部へ出さない、など)
- **同じ項目を 2 か所へ出せます**(`商品名` → `商品名` と `検索用商品名`)
- **固定値の列を足せます**(`公開状態` を全行 `1` にする、など)
- 文字コードは **UTF-8(BOM あり / なし)と Shift_JIS** から選べます
  (Windows の Excel で開くなら BOM ありが安全です)
- 引用符は「必要なときだけ」と「すべての項目」から選べます。
  カンマ・引用符・改行を含む値は必ず正しく囲みます(行の終わりは CRLF)
- 元のファイルは変更せず、同じフォルダーに `<元の名前>_変換済み.csv` を作ります。
  既にある同じ名前のファイルは上書きしません
- 作ったあと読み直して、項目名・行数・列数・各項目が指定どおりかを確かめてから確定します
- 何をどう変換したかは控えファイルに残ります(この PC の中だけ)
- Excel を元にする場合、数式・日付・時刻・通貨・パーセント・TRUE/FALSE のセルは
  **意味が変わる可能性があるため中止**します(そのままの文字か数値だけを扱います)

**次の機能はまだありません。** 条件で行を絞ること、並べ替え、重複の削除、
検索して置換すること、文字の正規化(全角半角など)、計算、日付の変換、
CSV 同士の結合、Web へのアップロード。

「どんな CSV でも変換できる」わけではありません。

### 8. PDF を読み取る(文字情報を持つ PDF から Excel / CSV へ)

**文字情報を持つ PDF**(パソコンで作られた PDF)から、文章や表を取り出して
新しい Excel / CSV を作ります。PDF を選ぶと、種類は自動で判定します。

- 通常の文字 PDF → **ページ / 行 / 内容**の 3 列で取り出します
  (どのページの何行目かが分かる形にします)
- 表 PDF → **そのままの行・列**で取り出します。罫線のある表も、
  罫線のない(位置で列が分かれている)表も対象です
- 複数ページに続く表は 1 つにつなぎます。2 ページ目以降で**まったく同じ見出し**が
  繰り返されている場合だけ、見出しをまとめます(少しでも違えばデータとして残します)
- 取り出した文字は Unicode の NFKC で正規化します。見た目が同じでも
  文字コードが違う字(康熙部首など)が混ざることがあるためです。
  それ以上の言い換え(表記ゆれの統一など)はしません
- 商品コード・電話番号・先頭が 0 の番号は**文字のまま**出します。
  数値にしても意味が変わらないと確実に言えるものだけ数値にします
- 出力は Excel(.xlsx)と CSV から選べます。CSV の文字コード・引用符は
  「7. CSV を変換」と同じ設定が使えます
- 元の PDF は変更せず、同じフォルダーに `<元の名前>_PDF抽出.xlsx`(または .csv)を
  作ります。既にある同じ名前のファイルは上書きしません
- 作ったあと読み直して、行数・列数・各項目が指定どおりかを確かめてから確定します
- 何をどう取り出したかは控えファイルに残ります(この PC の中だけ)

これは **PDF の見た目を Excel で再現する機能ではありません。**
PDF に含まれるデータを、Excel で扱える表の形にするための機能です。

#### スキャンした PDF(OCR)

**Offline OCR Pack** を一緒に置くと、スキャンされたページも読み取れます。
完全にオフラインで動き、通信・追加インストール・Python などは要りません。

- 画像のページだけを OCR にかけます。**文字情報のあるページは OCR を通しません**
  (元から正しい文字を画像にし直して精度を落とさないため)
- 2 つの認識モデル(数字・英字が得意なものと、かな漢字が得意なもの)で
  同じ場所を読み、結果を突き合わせます。片方だけでは、
  かな漢字か英数字コードのどちらかが必ず崩れることを実測しています
- 結果は **自動確定 / 要確認 / 読取不能** の 3 つに分かれます。
  2 つのモデルが一致し、かつ十分な自信があるものだけを自動確定にします
- **一致していても、形が怪しいものは自動確定にしません。**
  2 つのモデルは似た作りなので、同じ字形を同じように取り違えます。
  そのため「両方が一致した」ことが根拠にならない場合があります。実測では
  「S001-24」を両方とも「SO01-24」(0 が O)と読み、自信 98% で一致していました。
  そこで次の 2 つを足しています。どちらも**自動確定を見送って人へ回すだけ**で、
  読み取った内容を書き換えることはありません
  - コードの項目に 0 と O のような取り違えやすい字があるとき、
    数量・金額の項目に数字以外の字があるとき
  - 表の中で、同じ列の他の行と文字の種類が違うセル。
    切り出しが上下逆のまま読まれたものがここで見つかります
    (実測「A0096」→「9600」を自信 99.8% で自動確定していました)
- なぜ確認が要るのかは、選んだ項目の下に理由として表示します
- **元の PDF のページを見ながら確認します。** 選んだ項目のページが自動で表示され、
  読み取った場所が枠で示されます。文字が小さすぎるときは読める大きさまで自動で寄り、
  拡大・縮小・100%・全体表示・ページ送りも使えます。
  2 つのモデルが両方とも間違っていることもあるので、原文と見比べられることが要です
- **確認が済んでいない項目が 1 件でも残っていると出力できません。**
  「修正して確認 → 次へ」と「元のままで確認 → 次へ」で、
  原文を見ながら 1 件ずつ進めます(Enter / Ctrl+Enter / Esc / F3 でも操作できます)。
  一覧を開いただけでは確認済みになりません
- **まとめて確認済みにする操作はありません。** 原文と見比べずに確認済みにできると、
  この仕組みの意味が無くなるためです。代わりに「次の要確認へ」で速く進めます
- 一覧には人が見るべき項目だけを並べます。100 ページを超える PDF でも、
  全部を 1 件ずつ見る必要はありません。
  「自動確定も表示」で、自動確定した内容も原文と見比べられます
- 読み取りは中止できます。中止しても元の PDF は変わらず、ファイルも作りません
- 控えには件数(自動確定・要確認・読取不能・人が修正した数)だけを残します。
  **読み取った文字そのものは控えに残しません**

**OCR Pack が無くても本体は普通に起動し、文字情報のある PDF はそのまま読めます。**
スキャンされた PDF を選んだときだけ「OCR Pack がありません」と表示します。

#### 傾き・スキャンされた表・同じ様式の帳票・チェック

- **傾いたページは自動でまっすぐに直してから読みます。** 0.3 度未満は
  かえって粗くなるので直しません。6 度を超えるものは直さず、取り込み直しを促します。
  確認画面の赤い枠は**元の PDF 上の正しい位置**を指します
- **罫線のある表**は罫線から格子を作って行・列へ戻します。
  外枠の細い線が拾えなくても、その外側にある文字を捨てません
- **罫線のない表**は文字の位置のまとまりから列を決めて戻します
- **同じ様式の帳票**は「同じ様式の帳票として読む」を選ぶと、1 ページ 1 件で
  読み取ります。1 ページ目から項目の候補を自動で作るので、
  名前と種類を直すだけで使えます。項目名を手がかりにページごとのずれも吸収します
- **読めなかった項目は消えません。** 読む場所は分かっているのに何も読み取れなかった
  ときは「見つからない」として一覧に残り、元のページのその場所を見て手で入れられます。
  指定した項目の数と、確認する件数は必ず一致します
- **チェック・塗りつぶし・丸・ばつ**は文字として読まず、印の濃さで判定します。
  複数に印があるように見えるとき、薄いときは自動で決めず人へ回します

**まだ対応していないもの。** 傾いた罫線表(まっすぐな表とは精度が大きく違うため、
理由を表示して止めます)、1 ページに複数件の帳票、手書き。

### よく使う設定を保存する(処理設定)

毎週・毎月同じ作業をするとき、**設定に名前を付けてこの PC に保存**できます。
上の 4・5・6・7 の画面の上部にある「処理設定」から使います(「8. PDF を読み取る」は今のところ対象外です)。

例:「商品マスタ月次更新」という名前で、

- どの項目をキーにするか(データ元は `SKU`、転記先は `商品コード`)
- 項目名が何行目にあるか
- どの項目をどの項目へ入れるか(`単価` → `販売単価` / 数値)
- 出力名(`_更新済み`)

を保存しておくと、次回は

1. 「商品マスタ月次更新」を読み込む
2. 今回の CSV / Excel を選ぶ
3. 今回の転記先 Excel を選ぶ
4. プレビューを更新する
5. 実行する

の順で使えます。

- **Excel や CSV のファイルそのものは保存しません。** 場所(フルパス)も
  ファイル名も残さないので、毎月ファイル名が変わっても同じ設定を使えます。
  そのぶん、今回使うファイルは毎回選び直してください
- **読み込んでも自動では実行しません。** 読み込むと必ずプレビューが
  やり直しになり、いつもの確認と安全チェックを経てから実行します
- 保存できるのは、プレビューが最新で、実行できない問題が無いときだけです
  (「今回は変わるところが無い」だけなら保存できます)
- **実行して成功したあとも、そのままの設定なら保存できます。**
  作ったファイルが同じ名前で残っていてもかまいません。実際に成功した設定を
  「次回も使いたい」と思ってから保存する、という順番で使えます。
  そのあと設定を変えると、その変更は確かめていないので保存できなくなります
  (元に戻せばまた保存できます)
- 保存したシート名や項目名が今回のファイルに無いときは、**似た名前を
  勝手に使わず**、その名前を挙げて選び直してもらいます
- 保存先はこの PC の中(`%LOCALAPPDATA%\ExcelBatchTool\recipes.json`)だけです。
  クラウドや他の PC へは送りません
- このファイルは暗号化されていない通常のテキストです。入力した固定値・
  項目名・シート名がそのまま入るので、そのつもりで扱ってください
- 同じ名前があるときは黙って上書きせず、「更新」「削除」は確認してから行います

**次の機能はまだありません。** 設定の書き出し・読み込み(他の PC への持ち出し)、
クラウド同期、時刻を決めた自動実行、「表をまとめる」「シートをまとめる」の設定保存。

## 方針

- **Windows 専用**(.NET 8 / WPF)
- **Microsoft Excel 本体不要**(Office Interop 不使用。
  [Open XML SDK](https://github.com/dotnet/Open-XML-SDK) で直接読み取り)
- **完全ローカル**(クラウドサービス・外部 API・ログイン不使用。
  アプリ自身はネットワーク通信機能を持ちません)
- 対象は `.xlsx`(`.xls` は対象外)

## ビルド

.NET 8 SDK が必要です。

```
dotnet build
dotnet test
dotnet run --project src/ExcelBatchTool.App
```

## 配布用ビルド(self-contained)

配布版は self-contained(.NET Desktop Runtime の別インストール不要)の
Windows x64 構成です。

```
dotnet publish src/ExcelBatchTool.App -c Release -p:PublishProfile=win-x64-self-contained
```

出力: `src/ExcelBatchTool.App/bin/Release/net8.0-windows/win-x64/publish/`
(この中の `ExcelBatchTool.App.exe` を起動)

## Offline OCR Pack のビルド

スキャン PDF を読むための Pack は**本体とは別**に作ります。
本体の配布サイズには含まれません。

```
dotnet publish src/ExcelBatchTool.Ocr -c Release -r win-x64 --self-contained false -o <publish-dir>
dotnet run --project tools/OcrPackBuilder -c Release -- <publish-dir> <publish>/ocr
```

`OcrPackBuilder` は組み立てのときだけモデルを取得し、Pack の中に

- 認識・検出・向き判定のモデルと辞書
- 推論ランタイムと VC++ ランタイム(app-local)
- ライセンス表示(`LICENSES.txt`)
- 目録(`pack.json`。ファイルごとのサイズと SHA-256)

を入れます。**出来上がった Pack は自己完結していて、
実行時に通信も追加インストールもしません。**
本体は起動時に `ocr` フォルダーを探し、目録どおりに揃っているかを確かめてから使います。
欠けていたり中身が違っていたりすれば、native の読み込みに入る前に理由を表示して止めます。

## 構成

```
src/ExcelBatchTool.Core   … 解析エンジン(読み取り専用)
src/ExcelBatchTool.Core/Merge       … 表の縦結合(検証・ストリーミング読み書き)
src/ExcelBatchTool.Core/Aggregation … シートの集約(検証・書式の移植・出力検証)
src/ExcelBatchTool.Core/CsvTransform … CSV への変換(流し読み・書き出し・出力検証)
src/ExcelBatchTool.Core/Pdf         … PDF の読み取り(判定・文字/表の抽出・出力検証)
src/ExcelBatchTool.Core/Ocr         … OCR の統合規則・確認の状態・Pack の検査
                                       (OCR ランタイムそのものは持たない)
src/ExcelBatchTool.Core/Recipes     … 処理設定の保存(この PC の中だけ)
src/ExcelBatchTool.App    … WPF デスクトップアプリ
src/ExcelBatchTool.Ocr    … Offline OCR Pack の中身(本体からは参照しない)
tools/OcrPackBuilder      … Offline OCR Pack を組み立てる配布用ツール
tests/                    … テスト(架空データで生成した Workbook を使用)
```

本体は `ExcelBatchTool.Ocr` を参照しません。OCR の実体は Pack のフォルダーから
実行時に読み込みます。この分け方のおかげで、Pack が無くても本体は普通に起動し、
本体の配布サイズに OCR ランタイムが乗りません。

テストでは、解析・プレビュー・統合の前後でファイルの SHA-256 ハッシュ・サイズ・
最終更新日時を比較し、**入力ファイルを一切変更しないこと**を自動検証しています。
出力側も、生成したファイルを開き直して見出しと行数を検証してから確定するため、
途中で失敗しても壊れた `.xlsx` が残りません。
